01 · Why rebuild

The brand changed, and Material UI could not follow it.

Material UI made sense at the start: a complete set of components and patterns teams already understood. After the rebrand, every custom override meant fighting its styling. We chose React Aria for behaviour because it has no visual opinions and brings ARIA semantics, keyboard and touch support with it. Colour, spacing and typography were built from the brand guidelines, and icons came from Lucide.

04 · Phase 2: the token system

A refreshed look, and tokens that AI agents can use as well as people.

I am a secondary contributor, working with a lead designer and a lead engineer, on the audit, some of the components and the token rules. Phase 2 brings the product closer to the latest marketing website. Each token is named by its role, scoped to the property it is meant for, and carries a one-line description. The generated docs list every code token beside its Figma name, its value and that description, so an agent writing code has the same information a designer would use to choose it.

Three layers: primitives hold raw values, semantic roles alias primitives, and components bind to semantic roles and nothing else. The values below are the real ones.

The questions to ask before adding a token. The goal is a small set of specific roles.

QuestionDo thisWhy
A semantic token already resolves to this value in this role?Reuse it.Same role and same value means no new token.
Same value, different role?Create a new role token.Roles that match today can diverge later, as surface/default and surface/raised may.
Used by one component only?Create it in that component group, such as tag/border-focus.Keeps roles specific and easy to retire.
Used by two or more components?Create it in a shared group, such as status/warning-border.Avoids duplicate tokens for one meaning.
Only a primitive fits?Add the semantic role first, then bind to it.Components never bind to primitives.

06 · Rules the build enforces

The rules are checked by the build, not by a reviewer remembering them.

Figma-driven tokens

Tokens are generated from Figma Variables, so design and code cannot drift apart by hand-editing. Components can only use semantic tokens.

Build fails if a component contains a hard-coded colour or px value.

Accessibility by default

Components are built on React Aria Components. Every component has an automated axe accessibility test and keyboard tests.

Build fails if a component uses a raw button, input or select element.

Generated docs

Props tables and Figma-to-code mappings are generated. Every component needs a usage guide.

Build fails if any part of a component’s documentation is missing.

Careful releases

Each component and variant is checked against one story per variant value. Releases go through changesets with changelogs.

Build fails if a variant value has no story of its own.
